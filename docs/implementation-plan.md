# 核心合同与运行安全实施计划

基线：`f2b7a8d`。保留轻量 Go 单体、SQLite、固定服务配置、每用户凭据与白名单。
按阶段做小范围实现与验收；开发完成不等于推送、发布或生产准入。

## P0：数字合同与调用预算（已实现并完成合成验收）

目标：验证的数值必须与送往下游的数值一致；schema 与不透明结构化输出不被
中途 float64 解码舍入。参数准备不能耗尽预算后再取得完整下游时间。

验收：integer/边界/enum/const/multipleOf/组合/引用数值回归；JSON/SSE 真实
双跳及直接调用；非法参数零下游请求；合法 schema、参数、structuredContent
及元数据保真；既有大小边界不意外收紧；撤权/版本屏障不变。全量 Go/race、
vet/build、依赖校验及前端回归通过，独立审查无阻断问题。细节见数字合同文档。

## P1：schema 执行的可中止资源边界（最小实现已通过 Linux 合成验收）

目标：把发现准入/编译和调用验证的同步 CPU 工作纳入真正可停止的边界。
先评审可信一次性 helper 的最小集成，不用 goroutine 超时后留下计算继续跑。

验收：有界并发、有限 IPC、总预算内超时/取消后 kill+Wait，再释放容量；关闭
时回收；过载/故障脱敏；超时无业务下游请求；最终授权与目录代次屏障保留。
按已支持平台验证打包/启动与兼容，明确并非 OS 文件/网络 sandbox 或硬内存保证。
未验证平台不默认支持。历史设计见 schema-isolation-design.md；当前实现和明确限制见 schema-execution.md。

## P2：审计容量与 HTTP 生命周期（两切片已通过合成验收）

1. 审计先公开准确 retained/reserved/remaining/readiness，验证归档后容量和
   临界状态，明确维护路径；再设计有限紧急限制操作预留，覆盖其耗尽、重复操作、
   持久提交故障和撤权取消语义。不能无声丢审计或以仅内存撤权冒充持久成功。
2. 对齐 CLI HTTP 写预算与允许的服务操作预算，覆盖真实 HTTP/1.1、HTTP/2
   慢操作及 shutdown；未知结果不重放、不把下游已完成推断成客户端已收到。

## 明确不做

不替换 SQLite、不引入分布式队列/微服务/多实例权限一致性，不新增门户、通用
OAuth 平台、任意 MCP 托管或客户特判。不触碰真实凭据、业务系统或部署；生产
试点仍需既定安全门槛与独立授权。每阶段分别报告通过项、残留风险与下一步，
不因一个修复通过就关闭包含更广范围的历史 Issue。

P2 当前实现及边界见 [审计容量](audit-capacity.md) 和 [HTTP 预算合同](http-budget-contract.md)。

最终合并验收：368 个顶层 Go 测试、完整 race/vet/build、模块校验及前端回归通过。HTTP 最终 152 秒配置下，真实 61 秒 H1/H2 双跳均完整接收一次结果。未推送、部署或做真实业务试点。
