# 有界的一次性 schema helper

P1 将 schema 语义准入（含正则编译）、精确数值编译及调用验证放进可终止的
一次性子进程。不是 worker pool、新服务或数据库迁移；不改变授权/路由模型。

## 启用边界

- `cmd/gateway` 的实际可执行程序在 serve 模式默认自执行可信 helper：全网关
  共 2 个槽、零队列、每次 helper 最多 1 秒的取消预算，仍受更早的操作/调用方
  deadline 约束。预算从启动前算起，启动开销不会获得额外时间。
- 私有进程入口先于配置/凭据读取、SQLite、日志和网络监听。它只接收一份有界
  schema/参数并给出固定状态，不收到身份、凭据、下游地址或整份配置。
- 库调用可以通过 `Config.SchemaIsolation` 指定可信可执行文件的绝对路径、
  容量（1..16）和预算（1ms..120s）。该字段不接受配置 JSON，也不持久化。
  宿主必须在正常初始化前处理 `SchemaHelperArgument`，调用 `RunSchemaHelper`。
  路径/配置无效则拒绝构造；启动/运行失败也不会回退进程内验证。
- 未设置该运行时选项的旧库调用、`cmd/demo` 保留进程内兼容模式，**不具备
  本文隔离保证**。不要把测试里的普通 `New(cfg)` 当成隔离生产配置。
- 当前仅允许 Linux/macOS 的直接进程模型。本轮只在 Linux 验证，macOS 尚待
  实机验收；其他平台明确拒绝启用，不静默降级。多平台打包仍非本轮目标。

## 生命周期与失败语义

登记、关闭标志及容量共用独立互斥锁；没有无界等待队列。槽位覆盖启动、通信、
执行及 Wait。取消/超时会杀停直接子进程，确认 Wait 完成后才归还容量，不能
先返回再让后台 goroutine 继续验证。`Gateway.Close` 禁止新 helper、取消在途
helper，并在不持授权锁的情况下等待回收，再按原逻辑结束下游操作/关闭存储。

Kill/Wait 依赖操作系统回收，不承诺在 deadline 那一瞬间完成返回。独立预算
能停止昂贵同步正则，不是数学上严格的墙钟保证，也不是硬内存限制。

调用验证通过后仍检查原入口/绑定代次、策略、目录工具对象及服务 revision，
再获取下游容量、审计和凭据。撤权目前不主动取消尚未准入的 helper，但其独立
预算继续生效，最后授权屏障拒绝已撤销结果；不能把校验通过当成发出请求许可。
发现取消或版本失效不会发布迟到目录。发现内只复用本次准入已编译检查的不可变
schema 字节，不设跨请求缓存，调用时在新 helper 中重新编译。

无效参数仍返回参数不匹配；过载、启动/协议故障不会伪装为参数语义错误，超时
保持 context deadline/cancellation 身份。发现阶段的过载/启动/崩溃目前归入
通用失败诊断，尚无独立持久运维分类。所有失败均不重试业务调用。

## IPC 与信任边界

请求为 16 字节 `SI01` 头（操作、保留零位、两个长度）及最多各 64 KiB 的
schema/参数，要求 EOF、拒绝短包/额外数据/未知操作。操作仅有编译输入、编译
输出、验证输入。响应严格 8 字节 `SO01`+固定状态+保留零位，拒绝短包、额外
输出及未知值。父进程最多保留 8 字节 stdout，丢弃 stderr，不传回原始验证错误。

无 shell、无额外 FD、固定根目录工作路径，环境仅 `GOMAXPROCS=1`。helper
必须是不创建子孙进程的可信程序；不是运行任意用户插件的容器。它仍以同一用户
权限运行，**没有文件/网络 sandbox、OS 内存限额或恶意可执行文件隔离**。可执行
文件的所有权、完整性、发布替换属于受信部署边界；不能把私有参数当成认证方案。

## 验收与剩余风险

- 真正的昂贵正则验证在独立子进程中取消，不向业务下游发出请求。
- 记录合成 helper PID，取消/Close 返回后确认其已不存在；槽位恢复后健康任务
  仍可执行。覆盖并发登记/关闭、过载、崩溃、启动失败、短/坏/洪泛输出、清洁环境。
- 覆盖 Close 与验证并行、验证期间撤权、发现取消不发布，以及 P0 精确数字复用。
- 真正构建 CLI 后，在没有默认配置文件的目录执行私有入口，验证其不走正常启动；
  本轮 Linux 合成样本启动+简单执行约 6–7ms，不是生产性能/尾延迟承诺。
- 全量 Go 普通/race、vet/build、模块、前端和原授权竞态回归仍为合并门槛。

每次启动进程有成本；很大的目录可能在既有发现总预算内无法完成。不得为了过关
自动扩大操作预算，也不宣称代表性负载已验收。公平调度、OS 内存治理、其他平台
验收和更细的运维诊断仍是后续工作；不涉及真实下游试点或生产部署。
